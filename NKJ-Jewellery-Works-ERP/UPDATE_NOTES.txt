NKJ JEWELLERY WORKS - ERP PHASE 1 UPDATE
======================================

- Added a fixed owner sidebar/topbar across authenticated owner routes,
  including the owner invoice screen. The original invoice sheet and print CSS
  remain; print CSS hides site navigation.
- Public navigation now exposes Home and New Invoice only. Owner Login remains
  available through the footer.
- Added a PostgreSQL Flyway V1 migration with core business, inventory,
  booking/installment, finance, staff/payroll, audit and backup-history tables.
- Added allow-listed owner CRUD APIs for staff, attendance, salary, expenses,
  inventory, stock movements, bookings, installments and receipts, suppliers,
  purchases, payments, old-gold exchange, customers, karigars, repairs, leaves
  and shop settings.
- Added database status, sales/expense reports and audit-log views.
- Added a backend-only PBKDF2 invoice PIN verifier and one-time PIN tickets;
  new invoice create and print actions require verification.
- Persisted invoice rows in invoice_items as well as the full payload snapshot.
- Improved the owner dashboard; removed Total Billing Amount and the duplicated
  Quick Actions panel.
- Added project setup and folder structure documentation.

Run frontend:
  cd frontend
  npm install
  npm run dev

Run backend:
  cd backend
  mvn spring-boot:run

Backend port: 8086. Database: PostgreSQL, default database name nkj_billing.

IMPORTANT LIMITATIONS:
This update is ERP Phase 1, not the completed production ERP. The existing
custom password + TOTP session service is still used (not Spring Security JWT).
Email authenticator recovery, encrypted scheduled local/Google Drive backup,
Electron desktop packaging, booking PDF/receipt workflows, automated salary
policy/attendance reconciliation, complete stock-to-sales integration and
final profit & loss with COGS are not implemented end-to-end. Database Management
is read-only health/status, and Backup History is currently a read-only register.
The report value is labeled Operating Result Before COGS and is not final profit.
A live Maven build, Vite production build and PostgreSQL migration test must be
run on the target computer before deployment. Back up existing PostgreSQL data
before applying migrations.
